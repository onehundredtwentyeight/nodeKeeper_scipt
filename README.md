# nodeKeeper & remnainstall (v1.1.1)

Automated, zero-intervention deployment and management suite for **Remnawave Nodes** and **3x-ui Panels** with built-in system hardening, native Cloudflare WARP, multi-mode Caddy selfsteal reverse proxy, scheduled autonomous maintenance, and self-updating CLI.

---

## Versioning & Auto-Updates

`nodeKeeper` follows a structured versioning scheme stored in `install.sh` (`INSTALLER_VERSION`) and `nodeKeeper` (`NK_VERSION`):
- **Small change (patch):** increments the 3rd digit (`1.0.1`, `1.1.1`)
- **Medium change (minor):** increments the 2nd digit (`1.1`, `1.2`)
- **Global change (major):** increments the 1st digit (`2.0`)

### Upgrading an Existing Node (1.0 / 1.1 → 1.1.1)
Simply re-run the installer on any already-deployed node:

```bash
curl -fsSL https://raw.githubusercontent.com/onehundredtwentyeight/nodeKeeper_scipt/main/install.sh | bash
```

The installer detects the active `nodeKeeper` installation, shows the installed vs. new version, and offers to run an in-place upgrade (preserving all settings in `/opt/nodekeeper/nodekeeper.env`), which automatically:
1. Updates `/usr/local/bin/nodeKeeper` to `v1.1.1`.
2. Migrates ownership and permissions on `/opt/remnanode` (and `/var/log/remnanode`, `/var/www/html`) for the created `ADMIN_USER`.
3. Configures passwordless `sudo` (`NOPASSWD: ALL`) for `ADMIN_USER` so non-interactive tasks work without password prompts (also applied automatically during cron updates from `1.1` → `1.1.1` and manual upgrades from `1.0` → `1.1.1`).
4. Refreshes `/opt/nodekeeper/maintenance.sh` without resetting your maintenance schedule.
5. Registers the daily auto-update cron check.

You can also run a non-interactive upgrade directly:
```bash
curl -fsSL https://raw.githubusercontent.com/onehundredtwentyeight/nodeKeeper_scipt/main/install.sh | bash -s -- --update
```

### Automatic Updates via Cron (v1.1+)
Starting from `v1.1`, `nodeKeeper` registers a daily randomized cron job (`nodeKeeper update --auto`) that checks `INSTALLER_VERSION` on GitHub, verifies syntax with `bash -n`, and automatically installs the update + migrations whenever the remote version is higher than the installed version. Logs are written to `/opt/nodekeeper/logs/autoupdate.log`.

## Quick Start (One-Line Install via `curl`)

### 1. Interactive One-Prompt Setup (Ask Once, Run Unattended)
Run on a fresh Ubuntu/Debian node as `root`:

```bash
curl -fsSL https://raw.githubusercontent.com/onehundredtwentyeight/nodeKeeper_scipt/main/install.sh | bash
```
*(Or using the `remnainstall` entry point)*:
```bash
curl -fsSL https://raw.githubusercontent.com/onehundredtwentyeight/nodeKeeper_scipt/main/remnainstall | bash
```

The script asks for all parameters **once at the very beginning**, displays a summary, runs IP & censorship diagnostics (`ipregion` + `censorcheck`), and then completes the entire installation without any further prompts.

### 2. Zero-Touch Unattended Setup (With Config File or CLI Flags)
Copy [`nodekeeper.conf.example`](nodekeeper.conf.example) to `nodekeeper.conf`, fill in your values, and execute:

```bash
curl -fsSL https://raw.githubusercontent.com/onehundredtwentyeight/nodeKeeper_scipt/main/install.sh | bash -s -- --config /path/to/nodekeeper.conf --yes
```

Remnanode example with CLI flags:
```bash
curl -fsSL https://raw.githubusercontent.com/onehundredtwentyeight/nodeKeeper_scipt/main/install.sh | bash -s -- \
  --yes \
  --hostname "kvn-nl-01" \
  --mode "selfsteal-multi" \
  --domain "node.example.com" \
  --cf-token "cfut_..." \
  --panel-ip "203.0.113.10" \
  --secret-key "eyJub2RlQ2VydFBlbSI6..."
```

3x-ui Docker panel example (auto-generates random username, password, and port):
```bash
curl -fsSL https://raw.githubusercontent.com/onehundredtwentyeight/nodeKeeper_scipt/main/install.sh | bash -s -- \
  --yes \
  --hostname "kvn-xui-01" \
  --mode "3xui" \
  --panel-ip "203.0.113.10"
```

## Features

1. **Pre-Flight IP & Censorship Checks**:
   Runs `ipregion.sh` and `censorcheck.sh` before applying system modifications and saves reports to `/opt/nodekeeper/logs/`.
2. **Full Custom Hostname**:
   Prompts for the exact hostname without forcing a prefix.
3. **Core Networking & Security Stack**:
   - Enables TCP **BBR** (`fq` + `bbr`).
   - Installs and configures **Fail2ban** protecting the SSH port.
   - Installs **Docker Engine** & Docker Compose plugin.
   - Configures **UFW** firewall (opens SSH, 80, 443, and restricts `NODE_PORT` or the `3x-ui` panel port exclusively to your `PANEL_IP`).
4. **System Hardening & Service Directory Permissions**:
   - Creates a dedicated admin user (default: `node`) with an autogenerated 20-character password.
   - Grants passwordless `sudo` (`NOPASSWD: ALL`) and `docker` group permissions, plus ownership of `/opt/remnanode` and `/opt/3x-ui` (`docker-compose.yml` kept `600` owned by `ADMIN_USER` so secrets remain private while the admin can manage the stack without `sudo`).
   - Configures SSH public key authentication (auto-detects `/root/.ssh/authorized_keys` or accepts a custom key).
   - Disables root SSH login (`PermitRootLogin no`) and password authentication (`PasswordAuthentication no`).
5. **Unattended Cloudflare WARP**:
   - Automatically provisions native WireGuard WARP via `wgcf` with `Table = off` and `PersistentKeepalive = 25` (`wg-quick@warp` systemd service) without interactive prompts.
6. **Four Installation Modes**:
   - `basic` — Runs `remnanode` container only in `/opt/remnanode`.
   - `selfsteal-single` — Runs `remnanode` + `caddy:latest` listening on `/dev/shm/nginx.sock` with PROXY protocol and HTTP-01 challenge for single-server domains.
   - `selfsteal-multi` — Runs `remnanode` + custom-built Caddy (`caddy-dns/cloudflare` plugin) using Cloudflare DNS-01 challenge (`CLOUDFLARE_API_TOKEN`) so multiple servers can share a selfsteal domain.
   - `3xui` — Runs official `ghcr.io/mhsanaei/3x-ui:latest` container in `/opt/3x-ui` (`network_mode: host`), initializes random-by-default username, password, and port via `/app/x-ui setting`, restricts the panel port in UFW strictly to `PANEL_IP` (main/central node), and prints all access credentials in the final console summary.
7. **Autonomous Maintenance & Self-Updating CLI**:
   - Self-rescheduling maintenance cron (default: randomized 5–10 days interval) that pulls fresh Docker images, runs `apt upgrade`, executes optional custom hooks, runs censorship diagnostics, rotates logs older than 30 days, and reboots cleanly.
   - Daily `nodeKeeper` auto-update cron check against GitHub.

## `nodeKeeper` CLI Management Utility

After installation, run `nodeKeeper` from anywhere (available to both `root` and the created admin user):

```bash
# Open interactive control panel
nodeKeeper

# Show installed version
nodeKeeper version

# Show full status (containers, WARP, Fail2ban, BBR, maintenance & auto-update cron)
nodeKeeper status

# Switch installation mode on the fly
nodeKeeper mode basic
nodeKeeper mode selfsteal-single
nodeKeeper mode selfsteal-multi
nodeKeeper mode 3xui

# Check or apply script updates & manage auto-update cron
nodeKeeper update status
nodeKeeper update check
nodeKeeper update now
nodeKeeper update enable
nodeKeeper update disable

# Fix ownership/permissions on /opt/remnanode and /opt/3x-ui for ADMIN_USER
nodeKeeper fix-permissions

# Configure passwordless sudo (NOPASSWD) for ADMIN_USER
nodeKeeper fix-sudo

# Control maintenance schedule
nodeKeeper schedule status
nodeKeeper schedule enable
nodeKeeper schedule disable
nodeKeeper schedule freq 5 10
nodeKeeper schedule logs true
nodeKeeper schedule extra-cmd "docker system prune -af"

# Start / Stop / Restart active stack containers
nodeKeeper restart

# Temporarily disable server (stops containers & closes proxy/panel ports in UFW)
nodeKeeper disable

# Re-enable server
nodeKeeper enable

# View logs
nodeKeeper logs remnanode
nodeKeeper logs caddy
nodeKeeper logs 3xui
nodeKeeper logs maint
nodeKeeper logs tests
nodeKeeper logs autoupdate

# Full clean uninstall
nodeKeeper uninstall
```
